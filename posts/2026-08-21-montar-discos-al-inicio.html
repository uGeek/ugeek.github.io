Montar discos automáticamente al inicio en Linux con fstab
Si estás añadiendo un disco duro secundario, un SSD, un pendrive o una partición adicional a tu servidor o PC, la forma más limpia y estándar de dejarlo montado en cada reinicio del sistema es utilizando el archivo /etc/fstab.

En esta guía veremos paso a paso cómo identificar tu disco, cómo configurar el montaje automático y el fallo común por el cual no se monta la partición al arrancar.

1. Identificar el UUID de la partición

Para no depender de letras de dispositivo como /dev/sdb1 (que pueden cambiar en cada reinicio si conectas un pendrive), utilizaremos el UUID (Universally Unique Identifier).

Ejecuta en la terminal:
sudo blkid

O también:
lsblk -f

Verás una salida similar a esta:
NAME   FSTYPE LABEL UUID                                 MOUNTPOINT
sda
├─sda1 ext4         129e879f-1da7-43b7-a012-41d375840b7a /
sdb
└─sdb1 ext4   datos 8f7d9a10-4b2c-4e89-a912-3456789abcde
Copia el UUID correspondiente a la partición que deseas montar automáticamente (por ejemplo: 8f7d9a10-4b2c-4e89-a912-3456789abcde).

2. Crear el punto de montaje

Necesitamos una carpeta donde mapear el contenido del disco.

La convención habitual en Linux sugiere utilizar el directorio /mnt o /media. Si es para tu usuario personal, también puedes usar tu /home.

Creamos la carpeta:
sudo mkdir -p /home/angel/Disco1

3. Configurar el archivo /etc/fstab

Abre el archivo de configuración con tu editor favorito (nano, micro, vim...):
sudo nano /etc/fstab

Añade al final del archivo una nueva línea siguiendo esta estructura:
UUID=tu-uuid-aqui /home/angel/Disco1 ext4 defaults,nofail 0 2

¿Cómo funciona cada columna?

  1. UUID: Identificador único de tu partición.

  2. Punto de montaje: Ruta donde quieres ver los archivos (/home/angel/Disco1).

  3. Sistema de archivos: Tipo de formato (ext4, xfs, btrfs, ntfs-3g, exfat).

  4. Opciones de montaje:

    • defaults: Aplica las opciones predeterminadas (rw, suid, dev, exec, auto, nouser, async).

    • nofail: Muy importante. Evita que el sistema se bloquee al iniciar si el disco físico no está conectado, está dañado o falla. El sistema arrancará con normalidad sin entrar en modo emergencia.

  5. Dump (0): Usado por el comando dump para hacer copias de seguridad. Ponemos 0 para deshabilitarlo.

  6. Pass (2): Orden de verificación con fsck en el arranque.

    • 0 = No comprobar.

    • 1 = Disco raíz /.

    • 2 = Resto de discos o particiones.

⚠️ El error común: noauto vs auto / nofail

Si usas la opción noauto, estás instruyendo explícitamente a Linux para que NO monte la partición durante el arranque del sistema. Tendrías que ejecutar manualmente sudo mount /home/angel/Disco1 cada vez que enciendas el equipo.

Para un montaje automático y seguro en el inicio utiliza defaults,nofail.

  • Si el disco está formateado en NTFS (partición de Windows), usa el controlador adecuado:
UUID=tu-uuid-aqui /home/angel/Disco1 ntfs-3g defaults,nofail 0 2

4. Verificar sin reiniciar

Antes de reiniciar el sistema, comprueba que no hay errores de sintaxis en el archivo /etc/fstab.

  1. Desmonta si tenías el disco cargado previamente:

    sudo umount /home/angel/Disco1
  2. Simula el montaje de todas las entradas del fstab:

    sudo mount -a
Si la terminal no devuelve ningún error, significa que la sintaxis es correcta.

A partir de este momento, cada vez que enciendas tu PC o servidor en Arch Linux, Debian, Ubuntu o Raspberry Pi, el disco estará accesible automáticamente.
